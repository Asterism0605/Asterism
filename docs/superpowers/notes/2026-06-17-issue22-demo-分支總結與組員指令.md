## 1. 這個分支做了什麼

Issue #22 支線 A：**外部圖庫圖片自動辨識 + 同風格延展**。整條從「抓圖 → AI 分類 →
存 DB → API → 前端延展」都打通了。三層架構：

```
離線辨識（慢、用 AI、開發者本機跑）
  scripts/enrich/*  ── Pexels/Unsplash 撈圖 → CLIP 三層分類(styleGroup/medium/subMedium)
                       + node-vibrant 取色 → 寫進 Postgres(images 表)
        │
        ▼
資料層  Supabase Postgres（共用雲端，images 表，目前 239 筆）
        │  server/db.ts 用 DATABASE_URL 連
        ▼
API     server/  ── Express，GET /api/images 回全部圖
        │  vite proxy /api → localhost:3001
        ▼
前端    src/pages/ImageSpread.vue ── 點中心圖 → 同風格輻射 4 張 → 點一張變中心再延展
        src/services/image.service.ts ── 本地優先、不足才補 API
```

### 功能/修正清單（本分支相對 develop）
- **離線 CLIP 辨識管線**（`scripts/enrich/`）：撈圖、三層分類、取色、寫 DB。
- **Express API + Postgres**（`server/`、`scripts/schema.sql`）。
- **首頁/延展資料源分流**：首頁只讀本地概念照（無 `medium`）；延展本地優先、撈不滿才補 API。
- **延展同分洗牌**：`getRelatedImages` 依共享 style 數分層、同層隨機 → **每次 F5 延展出
  不同 4 張**，但保留相關度（最相關的永遠在）。
- **ImageSpread loading 狀態**：外部圖要等 API，載入中顯示 `Loading…`，**不再閃
  「Image not found」**。
- **CLIP 門檻調整 + 重算**：styleGroup 0.25→0.6、medium 0.30→0.5；`recomputeNeedsReview.ts`
  用既有 confidence 重算，現有 239 筆中 60 筆標記 `needs_review`。
- **FloatingImageNetwork 修正**：圖片非同步載入後重算座標，解卡片 opacity 永遠 0 的 bug。
- **Supabase 遷移工具**：`scripts/loadImagesFromJson.ts` 從 `images_dump.json` 灌資料。

## 2. 環境設定（第一次）

```bash
npm install
cp .env.example .env      # 然後填下面 4 個值
```

`.env` 內容（⚠️ 不要 commit，已被 gitignore）：

| 變數 | 說明 | 從哪拿 |
| --- | --- | --- |
| `PEXELS_API_KEY` | 抓 Pexels 圖用 | pexels.com/api（免費申請） |
| `UNSPLASH_ACCESS_KEY` | 抓 Unsplash 圖用 | unsplash.com/developers（免費申請） |
| `DATABASE_URL` | 連 Supabase | Supabase → Connect → Connection string（Transaction pooler, 6543） |
| `SERVER_PORT` | API 埠 | 預設 `3001` |

> **抓圖才需要 Pexels/Unsplash key**；只是要跑起來看 demo（連共用 Supabase）不用 key。
> Supabase 連線字串細節見 `2026-06-17-issue22-資料庫共用方案.md`。密碼有特殊字元要 URL-encode。

## 3. 組員常用指令

### 看 demo（最常用）
```bash
npm run server     # 開一個分頁跑 API（連 Supabase），開著別關
npm run dev        # 另一個分頁跑前端 → http://localhost:5173
```
- 首頁 `http://localhost:5173/`
- 外部圖延展（直接看）：`http://localhost:5173/images/ext-pexels-7688500/spread`
  （換網址裡的 id 就換風格，各組代表 id 見 `2026-06-17-issue22-組員討論...` 筆記）

### 抓新圖進圖庫（會寫進 `.env` 指向的 DB）
```bash
npm run enrich:images
```
- 第一次會下載 CLIP 模型（幾分鐘）。
- Pexels/Unsplash 各 9 組各撈 15 張 → CLIP 分類 + 取色 → 寫 DB。
- 寫入用 `ON CONFLICT (id) DO NOTHING`，**重跑安全、不會插重複**。
- ⚠️ `.env` 的 `DATABASE_URL` 指向哪，就寫到哪。指向 Supabase = 大家都看得到。

### 調過 CLIP 門檻後，重算 needs_review（不重跑 AI）
```bash
npx tsx scripts/recomputeNeedsReview.ts
```

### 空 DB 灌種子（新環境快速有資料，不用抓）
```bash
# 1. 先建表（Supabase SQL Editor 貼 scripts/schema.sql，或：）
psql "$DATABASE_URL" -f scripts/schema.sql
# 2. 從 images_dump.json 灌 239 筆
npx tsx scripts/loadImagesFromJson.ts
```

### 測試 / 型別檢查
```bash
npm run test           # vitest
npx vue-tsc --noEmit   # 型別檢查
```

## 4. 資料庫（重要）

- **已改用 Supabase 共用雲端 Postgres**（組長開 org，東京 region）。
- 組員**不用各自建 DB、不用灌資料**——拿到 `DATABASE_URL` 貼進自己 `.env` 就連同一個。
- 圖檔本身在 Pexels/Unsplash CDN，DB 只存 url，**不需要圖床**。
- 改完 `.env` **一定要重啟 `npm run server`**（dotenv 只在啟動時讀一次）。
- 詳細（建置、RLS、遷移、共用方式）見 `2026-06-17-issue22-資料庫共用方案.md`。
