# 首頁佈局方向（自用筆記，不進 spec）

## 結論一句話

**沿用現有的 `FloatingImageNetwork`（d3-force 散佈），不重寫成瀑布流、不裝套件**，做幾個小改就能達到「隨機散佈 + 浮動 + 往下滾」的效果。

## 為什麼不用瀑布流 / 不裝套件

- 「純瀑布流（Pinterest 欄位對齊）」會放掉隨機散佈的感覺，而我們就是要散佈感。
- 瀑布流套件（vue-masonry-wall 等）對我們是繞遠路 —— 主圖數量有上限，又已經有 d3-force 在跑。
- d3-force 本來就是「在一個平面上散佈」，把平面變高就能往下滾過一片散佈圖，沿用現成程式即可。

## 要做的三個小改

1. **高度 ∝ 圖片數量** —— 不要把高度寫死成「超級無敵高」（會太空曠）。讓高度跟著圖片數量長：圖多就高、圖少就矮，密度永遠剛好。demo 少組就矮、正式版多 styleGroup 就自動變高。
2. **向心調弱 + 初始 y 撒滿整高** —— 現在 d3-force 有 `forceCenter` 會把圖往中間聚；改成往下鋪滿整個高度，而不是擠中間。
3. **放開 `MAX_IMAGES`** —— 現在鎖死 6 張，要放開讓它能擺更多。

（散佈 + 浮動的視覺都保留；浮動是 CSS 動畫層，跟佈局無關。）

## 高度怎麼從數量算（為什麼是「高度先」）

順序是「**先用數量算高度，再在那個高度內隨機散佈**」，不是「先隨機再看要多高」。

```
① 數圖片數量 N
② 用 N 算高度 H（N 大就高、N 小就矮）   ← 高度先定
③ 把圖隨機散佈在 [0~H] 內              ← 隨機在 H 裡面跑
④ clamp 收進 [0, H]，超出拉回          ← 最低就是底部
```

- 隨機的範圍**本身就是 0~H**，一張圖最低只能到底部，**不可能掉出畫布**。
- 所以不會有「隨機到很下面、高度不夠」的問題 —— 是**高度先決定「最下面在哪」**，隨機只在裡面填。
- 你那個擔心（隨機可能超出高度）只在「無邊界亂撒」才會發生；我們是「有邊界、邊界＝H」。

H 怎麼算（讓密度恆定）：

```
H = (N × 每張平均佔位面積 ÷ 目標密度) ÷ 畫布寬度
→ N 多 H 高、N 少 H 矮，密度永遠一樣
```

d3-force 角色：`collide` 防重疊、`charge` 互斥推開、`clamp` 收邊 → 在固定高度內鋪均勻，不會上面擠一堆、下面一片空。

對照現有程式碼：`buildLayoutNodes` 本來就用 `height` 撒初始 y、`clampPosition` 收進 `[80, height-120]` → **只要把 `height` 改成「從數量算」，散佈/收邊邏輯都不用動。**

## 關於「無限滾動」

- **其實不會真無限。** 我們主頁的女團主圖、自己的照片都有上限，是有限的。
- 所以「一張很高的有限畫布」剛好符合需求 —— 不需要「滾到底 append 更多、重算」那種真‧無限機制。
- **登入牆**：訪客往下滾到一定深度 → 跳登入/加入會員提示。這是會員轉換的 gating，跟有限畫布並存，不衝突。

## 一句話總結

有限數量的主圖 → d3-force 散在「高度隨數量而定」的畫布上 → 往下滾、配輕浮動 → 中途撞登入牆。沿用現成元件，改三個小地方就好。
