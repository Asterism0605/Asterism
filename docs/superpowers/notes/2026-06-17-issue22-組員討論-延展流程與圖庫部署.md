## 2. 外部圖池（239 張）到底服務哪個流程

現在的落差（實機數據）：

| 資料源                    | 涵蓋的 styleGroup                                          | 張數 |
| ------------------------- | ---------------------------------------------------------- | ---- |
| 本地 `style-data.json`    | **只有 3 組**：Y2K(20)、Future Tech(20)、Decorative(21)    | 61   |
| API 圖池（PostgreSQL）    | **全 9 組**                                                | 239  |
| 只在 API、本地沒有的 6 組 | Street / Retro / Minimal / Earth / Romantic / Experimental | —    |

**關鍵結論**：

- 外部圖池是為「**同風格無限延展**」設計的（本地撈乾 → 外部接手）。
- 若主流程改成「**逐層下鑽**」，本地策展樹永遠夠用 → **這個流程根本用不到外部池**。
- 而且那 6 個只在 API 的組，目前從首頁完全進不去（首頁只有 3 張本地概念照）。

**要決定外部池的定位（三選一）**：

- **A. 維持本地優先**：外部當「看光本地後的後備／無限捲動」。
- **B. 固定混搭**：每次延展固定混 N 張本地＋M 張外部，讓外部一定露臉。
- **C. 外部為主**：本地只當入口，延展主打 AI 長出來的圖庫。

## 3. CLIP 分類品質 & 信心門檻（已先調，給組員過目）

- 門檻 `scripts/enrich/taxonomy.ts`：styleGroup **0.25→0.6**、medium **0.30→0.5**
  （subMedium 維持 0.35）。
- 原因：舊門檻太低，239 張**沒有一張**被標記要複查；且實機 styleGroup 信心中位數
  0.95 反而比 medium 0.74 高，推翻了原本「越細越嚴」的假設。
- 用 `scripts/recomputeNeedsReview.ts` 重算現有 239 筆 → **60 筆**被標記
  `needs_review = true`。
- 在 TablePlus 撈要複查的圖：
  ```sql
  SELECT id, style_group, medium, sub_medium, url,
         confidence->>'styleGroup' AS sg_conf,
         confidence->>'medium' AS md_conf, needs_review
  FROM images
  WHERE (needs_review->>'styleGroup')::bool
     OR (needs_review->>'medium')::bool
     OR (needs_review->>'subMedium')::bool
  ORDER BY (confidence->>'styleGroup')::float ASC;
  ```
- **附帶問題**：`SUBMEDIUM_BY_MEDIUM` 目前只定義 Graphic Design 的子類，
  Outfit / Interior / Architecture 永遠拿不到 subMedium（詞庫沒補齊，非 bug）。
  → 若主流程要下鑽到 subMedium，這份詞庫一定要補。
